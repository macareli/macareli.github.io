## User paths

1. Home → Download for Android → `/release/` → Download APK (same-origin actual file).
2. Home → Explore the app → select Chat, Create, Discover, or Your space → matching real screenshot and feature description.
3. Keyboard users can enter the feature tabs, use Left/Right/Home/End, and Tab into the selected panel.
4. Home → expand a question → read product, AI-provider, import, install, or pricing information.
5. Any page → theme toggle → light/dark preference persists on the same origin when browser storage is available.
6. Release → native install/update accordions → platform instructions.
7. Release → Copy checksum → copied status, or selected-text fallback when Clipboard API is unavailable.
8. Footer → source or issues on the actual public MaiChat repository.

## Data and verification

No mock service, testimonial, engagement statistic, AI conversation backend, or fabricated performance claim is present. Feature screenshots are actual app captures supplied by the screenshot worker; the final stable capture assets must replace provisional source images before publishing. Product copy is grounded in the supplied repository/product facts. The release file and metadata are supplied by the build agent.

`python3 scripts/check_material.py src` was run. Real token findings were fixed. The checker treats each component/template in isolation and therefore initially flags missing focus rules on HTML files even though all import the shared `shell.css` focus rule, and missing skip link in page sources even though `{{header}}` renders one. It also flags a generated-scheme comment that continues on a second line. Integration should check assembled pages and shared CSS together or record those narrow static-checker limitations. Real browser accessibility and layout tests take precedence over these per-file false positives.

The CSS uses one globally defined 3px `:focus-visible` rule, local tab focus offset, native controls, minimum 48px control targets, state layers, and reduced-motion media queries. Local fonts avoid external font requests. Hero image has explicit aspect ratio dimensions and high fetch priority; feature images are lazy-loaded.

See DESIGN.md for token choices and deliberate exceptions. The controller and tester reviews are coordinated by the main agent after building; this UI builder does not self-certify those independent passes.

A branded `src/pages/404.html` and root `manifest.webmanifest` are supplied. The 404 uses the same shared shell and palette and gives native links home and to the download page. Both font distributions include their SIL Open Font License text in `assets/fonts/`.

Integration: the checker now resolves shared linked stylesheets with `--site-root _site` and ignores multiline documentation comments. `python3 scripts/check_material.py --site-root _site _site` passes with zero findings. Twenty page/width/theme variants pass axe with zero WCAG A/AA violations; full same-site APK browser download matches the official SHA-256. Production app JavaScript is 3,159 bytes before compression.

Responsive screenshot delivery copies are generated by Sharp from the unaltered 1440 × 3120 native PNG captures, at 240/320/480/720/1440 widths. Pages use srcset/sizes; originals remain available at their PNG paths. No screenshot content is retouched. Google Material Symbols Rounded SVGs replace the provisional icon paths; see DESIGN.md and assets/material-icons-LICENSE.txt.
